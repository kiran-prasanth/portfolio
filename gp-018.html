GP-018 In Progress

Sprint board auto-archive rule — close completed tickets from active board view after 7 days without blocking retrospective access

Story Medium priority Sprint 11 Delivery Ops Jira Config 5 pts
Context

The active sprint board accumulates completed tickets over time as sprints close without a cleanup process. By Sprint 10, the board was showing 60+ tickets per sprint view, making it difficult for the team to quickly identify in-progress items and for the PM to spot tickets that had stalled. This added friction to daily tracking and made the board unusable as a real-time delivery view.

At the same time, completed tickets need to remain accessible for retrospectives, audit, and client reporting. A hard delete or archive that removes them from reporting is not acceptable.

User Story
As the Project Manager running a sprint,
I want completed tickets to be automatically removed from the active board view 7 days after they are closed,
so that the board only shows work that is active or recently closed, making it easier to track real-time delivery without losing access to historical ticket data for retrospectives and reporting.
Acceptance Criteria
  • Tickets with status "Done" are automatically moved out of the active sprint board view exactly 7 days after their resolution date. The 7-day window is configurable by the PM from the board settings without requiring admin access.
  • Archived tickets remain fully accessible in: (1) the completed sprint archive, (2) the backlog with their original sprint label intact, (3) all Jira reports including velocity charts and sprint reports. No data is deleted or hidden from reporting.
  • The board filter includes a visible "Show archived" toggle that any team member can use to surface archived tickets in the current board view temporarily, without requiring a separate search query.
  • When a ticket is auto-archived, no notification is sent to the assignee or reporter. The action is silent and reversible.
  • If a closed ticket is reopened within the 7-day window (e.g., due to a QA failure), it returns to the active board immediately and the 7-day clock resets from the new close date.
  • The PM receives a weekly digest (in the existing delivery report format) showing how many tickets were auto-archived in the past 7 days, with a link to the full list.
Edge Cases and Constraints
  • Sprint close with open tickets: If a sprint is closed with tickets still in progress, those tickets must not be auto-archived even if they age past 7 days. The 7-day rule applies only to tickets in "Done" status.
  • Retrospective window: Auto-archive must not trigger before the sprint retrospective has been conducted. The sprint retro date is logged in the sprint description. If no retro date is recorded, the 7-day clock still applies but PM is notified before archiving.
  • Jira plan dependency: Auto-archive behaviour depends on the Jira plan tier. If the current plan does not support automated status transitions at the required granularity, a manual admin rule using Jira Automation is the acceptable fallback. Delivery Lead to confirm plan capability before implementation begins.
  • Bulk archive: If more than 20 tickets are due to be archived in a single automated run, the system flags this to the PM for manual review before proceeding. Prevents a misconfigured rule from silently clearing the board.
Technical Notes (for devs / Jira admin)
Implementation via Jira Automation: create a scheduled rule that runs daily at 00:00 IST. Condition: status = Done AND resolutiondate <= -7d. Action: transition ticket to a new "Archived" status and apply label auto-archived. The "Archived" status must be excluded from the default board filter via a JQL board filter update: status not in ("Archived").

The "Show archived" toggle on the board is a saved filter toggle — not a new component. Configure a secondary filter named "All including archived" and surface it as a board view option. No new UI development required.

Weekly digest: use the existing Jira Automation email action. Trigger: scheduled weekly. Filter: label = auto-archived AND updated >= -7d. Send to PM email only.
Definition of Done
  • Automation rule live in staging Jira environment and confirmed working on test tickets
  • Archived tickets confirmed visible in completed sprint report and backlog view
  • "Show archived" board toggle confirmed functional for all team members
  • Reopen edge case tested — ticket returns to active board immediately on reopen
  • Bulk archive threshold tested — PM notified correctly when threshold exceeded
  • Weekly digest email confirmed delivered to PM with correct ticket list
  • PM signed off after testing in staging before rule is promoted to production
