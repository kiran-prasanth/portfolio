Context

Brandshark is a 12-person design and development studio running 12-15 concurrent client projects across brand identity, digital platforms, and marketing assets. When I joined as Project Manager in January 2025, the studio had no shared delivery process. Sprint structure was informal, there was no RAID log, status updates were reactive, and scope changes were absorbed without any formal assessment or sign-off.

The result was predictable: frequent mid-project misalignment, revision cycles that could have been avoided, and delivery timelines that slipped without a clear audit trail for why.

Before and After
Before
  • No shared sprint structure or ceremony format
  • Scope changes absorbed verbally with no log
  • Status updates sent reactively when asked
  • No RAID log — blockers surfaced in standup only
  • No standard for handoff between delivery stages
After
  • Weekly sprint planning, daily check-ins, structured reviews
  • All scope changes logged, assessed, and signed off before entry
  • Proactive weekly status report sent to department heads
  • Live RAID log across all 12-15 active projects
  • SOP covering kickoff through sign-off adopted team-wide
What I Built
SOP-01
Project kickoff to delivery SOP
Covers scope definition, milestone setting, acceptance criteria, sprint structure, review gates, and final sign-off. Adopted across all client verticals within 6 weeks.
SOP-02
Scope change request process
All scope changes are logged in a change request form, assessed for impact on timeline and effort, and approved by the client before touching the delivery plan. Zero uncontrolled scope since implementation.
RAID
Live RAID log across all active projects
Single Notion database tracking risks, issues, assumptions, and dependencies with owner, due date, status, and escalation flag. Reviewed weekly with department heads.
RPT
Weekly delivery status report format
Structured one-page report for department heads: project status, milestone progress, open risks, blockers requiring decisions, and carry-over items. Sent every Friday without being asked.
Outcome

Maintained 95% on-time delivery across 12-15 concurrent projects from month 2 onward. Scope changes reduced from an average of 3-4 uncontrolled changes per project to zero uncontrolled changes — all absorbed within the delivery plan without deadline extensions. The delivery workflow SOP was adopted by the team without enforcement; it became the default because it made execution easier.
