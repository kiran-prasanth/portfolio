Self-service brand asset portal so clients can access approved files without raising a studio request

Feature High priority Sprint 7 Web Dev · Design Systems Estimate: 8 pts
Context After brand delivery, clients repeatedly contact the studio via email or WhatsApp to retrieve assets — logo variants, colour codes, font files, brand guideline PDFs — that were already handed over. This creates noise in the studio's project channels, delays the client, and pulls designers away from active projects. A lightweight self-service portal, scoped per client, will eliminate this recurring overhead entirely.

User Story

As a client who has received a completed brand identity from Brandshark,
I want to access all my approved brand assets from a single, organised portal at any time,
so that I can download the exact file I need — in the right format — without contacting the studio or waiting for a response.

Acceptance Criteria

  • Each client receives a unique, password-protected portal URL after project handoff. Accessible via any modern browser with no app installation required.
  • Assets are organised into named sections: Logo Variants, Colour Palette, Typography, Brand Guidelines, and Miscellaneous. Sections with no uploaded files are hidden automatically.
  • Logo Variants section displays each logo with a thumbnail preview, file format label (SVG, PNG, PDF), and an individual Download button. Clients can also trigger a "Download all logos as ZIP" action.
  • Colour Palette section shows each brand colour as a visual swatch alongside its HEX, RGB, and CMYK values. Values are individually copyable via click-to-copy with a confirmation tooltip ("Copied!").
  • Typography section lists each brand typeface with its name, classification (Primary / Secondary), and a "Get font" link (Google Fonts URL or downloadable file, depending on licensing).
  • The studio admin can upload, replace, or remove files per client from a backend CMS without requiring a developer. Changes reflect on the portal immediately upon save.
  • Every file download is logged (timestamp, file name, client portal ID) and viewable by the studio admin. No PII beyond the portal session is collected.

Edge Cases & Constraints

  • !Expired or revoked access: If the studio deactivates a portal, the client sees "This portal is currently unavailable — contact your account manager." No assets visible or downloadable.
  • !Large file downloads: Files above 25 MB should trigger a progress indicator. If a download fails mid-way, display a retry option rather than a blank error state.
  • !Mobile access: Swatches, thumbnails, and download buttons must be fully functional on viewport widths from 360px upward.
  • !Font licensing: Commercially licensed typefaces must not offer a direct download. Display "Licensed font — contact studio" to avoid redistribution liability.

Technical Notes (for devs)

Portal pages are generated per client. Each has a unique slug: /portal/{client-slug}. Authentication via token-in-URL or a one-time password to the client's registered email — no account creation required.

File storage: assets stored in a private S3-equivalent bucket. All download links should be signed/time-limited URLs — never expose raw bucket URLs to the client-facing layer.

Click-to-copy: use navigator.clipboard.writeText() with a fallback for older browsers. Tooltip confirmation auto-dismisses after 2 seconds.

CMS panel: scope admin access to "Brand Manager" role only. Log all CMS file operations for audit purposes alongside the download log.

Definition of Done

✓ Portal renders correctly on desktop and mobile (360px min)
✓ All sections function and hide gracefully when empty
✓ Click-to-copy works for all three colour value formats
✓ Download log confirmed capturing entries in admin view
✓ Revoked portal access tested — no assets visible post-deactivation
✓ Studio admin uploaded test assets via CMS without dev help
✓ PM has signed off the build against every AC before client handoff
