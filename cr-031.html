CR-031  ·  In Progress

AI-powered content brief generator — analyse top-ranking SERP results for a keyword and output a structured brief ready for writers

Feature High priority Sprint 5 AI · NLP · SaaS Estimate: 10 pts
Problem CometRank users track keyword rankings and identify content gaps — but the next step, actually briefing a writer to close those gaps, happens entirely outside the platform. Users export data, manually study competitor pages, and hand-craft briefs in Google Docs. This context switch is slow, inconsistent across teams, and breaks the CometRank workflow right at the moment of highest intent. This feature brings AI-driven brief generation in-product: a user enters a target keyword, the system analyses the top 10 ranking pages, and delivers a structured, writer-ready brief without leaving the platform.

Pipeline Overview

User inputs keyword→ SERP data fetch→ Top 10 page scrape→ Signal extraction→ LLM brief synthesis→ Brief rendered in-app→ Export / assign to writer

User Story

As a content strategist using CometRank,
I want to generate a structured content brief for any target keyword directly inside the platform,
so that I can brief writers with data-backed recommendations on headings, word count, semantic keywords, and competitor gaps — without manually analysing competitor pages or switching to a separate tool.

Brief Output — What Gets Generated

Recommended structure
H1 / H2 / H3 outline
AI-suggested heading hierarchy derived from patterns across top 10 ranking pages
Content depth signal
Target word count range
Min / max range based on median word count of top 10 results, with outlier exclusion
Semantic coverage
NLP keyword clusters
Entity and topic clusters that appear across top-ranking pages and should be covered
Gap analysis
Questions to answer
PAA (People Also Ask) and forum questions not adequately answered by current top results
Competitive intel
Competitor snapshot
Title, URL, estimated word count, and DA score for each of the top 10 ranking pages
Meta suggestions
Title & meta desc drafts
Three AI-generated title tag and meta description options following length and CTR best practices

Acceptance Criteria

  • User enters a target keyword in the Brief Generator input. The system fetches live SERP data for that keyword (Google, English, configurable country) and returns the top 10 organic results within 8 seconds. Ads, featured snippets, and local packs are excluded from the analysis set.
  • The system scrapes the body content of each of the top 10 URLs. Pages that return a non-200 status, require JavaScript rendering beyond a 3-second threshold, or are behind a login wall are skipped and replaced with the next available organic result. The brief is generated from a minimum of 7 successfully scraped pages; if fewer than 7 are available, the system notifies the user and proceeds with available data.
  • Signal extraction produces: (a) word count per page, (b) all H1–H3 heading text, (c) top 30 noun phrases by TF-IDF score, (d) internal and external link counts. These signals are passed as structured context to the LLM prompt — raw HTML is never sent to the LLM.
  • The LLM generates a brief containing all six output sections defined above. The brief is rendered in-app in an editable rich-text format. Users can edit any section directly before exporting or assigning to a writer.
  • Brief generation completes within 45 seconds of keyword submission for the full pipeline (SERP fetch → scrape → extract → LLM). A progress indicator with stage labels ("Fetching results...", "Analysing pages...", "Generating brief...") is shown throughout.
  • Each generated brief is saved automatically to the user's Brief History, linked to the originating keyword and the project it was generated under. Users can re-generate a brief for the same keyword at any time; both versions are retained in history.
  • Completed briefs can be exported as a formatted PDF or copied as a Markdown block. A "Assign to writer" action sends the brief via email to a specified address with a read-only view link — no CometRank account required for the recipient.
  • Brief generation consumes 1 credit from the user's monthly allowance. Credit deduction occurs only upon successful brief delivery, not on initiation. If generation fails, no credit is deducted and the user is notified with a retry option.

Edge Cases & Constraints

  • !Paywalled or bot-blocked pages: If a top-ranking page returns a CAPTCHA, 403, or Cloudflare challenge, it is silently skipped and replaced. Do not expose the failed URL or error to the user — only surface a count of "pages analysed" in the brief metadata.
  • !Very short SERP results: For niche or low-volume keywords, fewer than 10 organic results may exist. The system must handle SERPs with as few as 4 results gracefully — generate the brief with available data and flag reduced confidence with an inline notice on the brief.
  • !LLM hallucination guardrail: The LLM prompt must explicitly instruct the model to base all heading suggestions and keyword recommendations only on the extracted signals provided in context. If the model cannot produce a section from the given context, it must output a clearly marked placeholder — never fabricate data.
  • !Duplicate keyword requests: If the same user requests a brief for the same keyword within 24 hours, serve the cached brief instantly and offer a "Re-generate with fresh data" option rather than auto-consuming another credit.
  • !Credit exhaustion: If a user has 0 credits remaining, the Brief Generator input is disabled with a clear upgrade prompt. Do not allow generation to begin and fail mid-pipeline on credit grounds — gate at entry.
  • !Non-English SERPs: Brief generation is supported for English-language SERPs only in this release. If a user's project is set to a non-English locale, display a "Brief Generator available for English markets only — coming soon for other languages" notice and disable the feature for that project.

Technical Notes (for devs)

SERP data source: Use the DataForSEO SERP API (POST /v3/serp/google/organic/live/advanced) rather than scraping Google directly. Pass keyword, location_code, and language_code from the user's project settings. Cache SERP results for 24 hours per keyword+locale combination to reduce API spend.

Page scraping: Use a headless Chromium instance (Playwright) with a 3-second JS render timeout. Strip all nav, header, footer, aside, and script elements before content extraction — only extract content within article, main, or the largest text-density block if semantic tags are absent. Output clean text + heading structure only.

Signal extraction: TF-IDF noun phrase extraction should run server-side using a lightweight NLP library (spaCy or compromise.js). Build the IDF corpus from the scraped page set itself — do not use a pre-built general corpus, as SEO content has a very different term distribution. Output the top 30 phrases ranked by score.

LLM prompt design: Use a system prompt that defines the PM's role as "SEO content strategist" and explicitly constrains the model to the provided signals. Pass signals as structured JSON in the user message, not as prose. Use temperature: 0.3 for consistency across re-generations. Model: claude-sonnet-4-20250514 or equivalent. Max output tokens: 2000.

Credit system: Credits are stored in the workspace.credits_remaining field. Deduct via an atomic DB transaction only after the brief is fully written to the briefs table. If the write fails, roll back the credit deduction. Never deduct on pipeline initiation.
